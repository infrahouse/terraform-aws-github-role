## What this module does

A small Terraform module published to the registry as `infrahouse/github-role/aws`. It creates a single
`aws_iam_role` whose trust policy lets a GitHub Actions runner in a specific `gh_org_name/repo_name`
assume it via OIDC (`sts:AssumeRoleWithWebIdentity`). It attaches **no** permission policies — consumers
attach their own policies to the returned role (`github_role_name` / `github_role_arn` outputs).

The trust relationship depends on a pre-existing GitHub OIDC provider in the AWS account, looked up via
`data.aws_iam_openid_connect_provider.github` (URL `https://token.actions.githubusercontent.com`). This is
not created here — it comes from `terraform-aws-gh-identity-provider`, set up once per account.

The whole module is essentially `main.tf` (the role) + `data_sources.tf` (the OIDC lookup and trust policy
document). `variables.tf`, `outputs.tf`, `locals.tf`, `terraform.tf` are the standard surrounding files.

## Common commands

```bash
make bootstrap     # install Python deps (pip install -r requirements.txt)
make lint          # terraform fmt --check -recursive
make format        # terraform fmt -recursive + black tests
make test-clean    # run tests against real AWS, then destroy (run this before a PR)
make test-keep     # run tests but keep AWS resources for debugging
make test          # bare `pytest -xvvs tests` (no AWS args; usually use test-clean instead)
```

Run a single test case:
```bash
pytest -xvvs --aws-region=us-west-2 --test-role-arn=<arn> \
  "tests/test_module.py::test_module_aws_versions[~> 6.0]"
```

## Testing model

Tests are pytest using `pytest-infrahouse` fixtures and **provision real AWS infrastructure** — they need
valid AWS credentials. The fixtures `aws_region`, `test_role_arn`, `keep_after`, `boto3_session` come from
the plugin and are supplied via the `--aws-region` / `--test-role-arn` / `--keep-after` CLI flags (see the
Makefile for the default region `us-west-2` and test role).

`tests/test_module.py::test_module_aws_versions` is parametrized over AWS provider versions `~> 5.11` and
`~> 6.0`. To do this it **rewrites `test_data/test_module/terraform.tf` and `terraform.tfvars` and deletes
`.terraform.lock.hcl`** on each run — so those files under `test_data/test_module/` are generated, not
hand-authored. `test_data/test_module/main.tf` invokes the root module via `source = "../../"`. The test
applies the config, then asserts via boto3 that the IAM role actually exists.

## Versioning

The module version lives in **three places that must stay in sync**: `locals.tf` (`module_version`, which
is stamped onto the role as a tag), `README.md` (the usage example), and `.bumpversion.cfg`. Use
`bump2version` (`bumpversion`) to change the version — it updates all three, commits, and tags. Don't edit
the version by hand.

## Conventions and automation

- **Commit messages must be Conventional Commits** — enforced by `hooks/commit-msg`. Types: feat, fix,
  docs, style, refactor, perf, test, build, ci, chore, revert, security (optional `!` for breaking).
- `make install-hooks` (run automatically by `make help`) symlinks `hooks/pre-commit`. The pre-commit hook
  enforces `terraform fmt`, regenerates `README.md` via `terraform-docs` (staging it), and requires every
  file to end with a newline.
- **README inputs/outputs/resources tables are generated by terraform-docs** (config in
  `.terraform-docs.yml`). Edit variable/output descriptions in the `.tf` files, not the tables.
- Max line length 120; all files end with a newline (see `.claude/CODING_STANDARD.md`).
- `hooks/*` and `.claude/CODING_STANDARD.md` are **managed externally** by the `infrahouse/github-control`
  repo and will be overwritten — change them there, not here.
